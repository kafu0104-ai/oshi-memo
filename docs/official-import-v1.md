## 実装内容

### Phase 1：抽出

- 年月日の日本語、スラッシュ、ピリオド表記に対応した候補抽出を追加。明示された開催年が一意の場合だけ年省略を補い、確認対象にする。終了年省略の年またぎも翌年候補として明示する。年が不明な原文は未確定候補に残す。
- OPEN / START、開場17:00、17時開場などを認識。隣り合う開場・開演時刻を取り違えないテストを追加。
- JSON-LDの出演者、開始・終了時刻、会場住所、詳細URL、複数イベントを抽出。時刻帯が日本と異なる情報は原文の時刻帯を示し、勝手に日本時間と扱わない。
- HTMLの公演カード、見出しと本文、同一会場の複数日程から、日付・会場・時刻の組を保持。公演候補を複数選べる。
- 既存の事前抽選抽出を維持し、当落発表／抽選結果発表／当選発表の表記と明示された結果時刻に対応。終了済み応募期間は新しいイベント読み取り候補から除外。
- 受付開始・当落時刻の単独記述は開催時間と区別した参照候補に保存。チケット管理データの自動生成は行わない。

### Phase 2：探索

- 最大8ページ、2階層、同時2件。同一HTTPSオリジン内の開催概要、日程、会場、申込等のリンクを優先。
- 1回の探索操作は45秒を上限とし、既存サーバーの制限も維持。Studioの補助JSONとDNS照会はHTMLページ数とは別の既存補助リクエスト。
- 項目指定の再探索は同じセッションの取得済みURLと上限を共有。重複・転送後URLの再取得を防止する。「読み込む」を押し直すと新しい取得セッションになる。
- 関連ページの別オリジンへの転送はサーバー側でも取得前に拒否。既存の公開URL確認、DNS確認、サイズ制限は維持。
- 明らかな別年度ページを除外。同一イベントと断定できない関連ページは要確認候補として分離し、自動反映しない。

### Phase 3：確認・保存

- found / notFound / ambiguous / unsupported / notApplied / error を保持し、日本語で表示。
- 候補の値、出典URL、短い根拠、取得日時、HTML / JSON-LD / Studioの取得方法を保存。
- 候補は初期状態では未選択。利用者が選んで「選択した情報を反映」を押した場合だけ入力欄を更新。既存入力と異なる値を画面で明示する。
- 基本情報の日程・会場・時刻は同じ候補からまとめて選択する。別公演は公演単位で追加する。
- イベントに任意の `officialImport` プロパティを追加。過去のイベントでは未設定のままで動作し、既存のイベント配列・バックアップ形式を利用する。同期・認証の実装は変更していない。
- 保存後、イベント詳細と編集画面から出典、反映状態、保存した候補を確認できる。手編集後は読み取り時点の記録として表示する。
- 簡易登録／物販以外では抽選候補を表示・保存するが、事前抽選登録は従来の物販詳細フォームから行うことを明示する。

## 残る制約・未対応

- 指示どおり、PDF本文・画像OCR・汎用JavaScriptレンダリング・AI解析は今回の対象外。未対応理由を表示する。
- 同一オリジンを超える別ドメイン／サブドメインのチケットサイト等は自動巡回しない。必要ならそのURLを明示して別途読み込む。
- 任意のサイト構造を完全に解析する汎用機能ではない。上限を超えるページ、見出しの対応が不明な情報、複雑な表などは確認候補または手入力となる。
- 同名・同年度の別イベントを必ず自動識別できるわけではないため、関連ページの情報は確認対象とし、候補を利用者が選ぶ。
- 実クラウド上の同期・認証の結合テストは未実施。既存コードと設定を保持し、スナップショット互換性をローカル検証した。
- 既存の表示テスト3件と、DBテスト用の既存依存不足は残る。今回の機能テストはすべて成功しているが、全体テストが完全成功した状態ではない。
- 公開・ステージング反映は行っていない。新しいAPI契約、依存パッケージ、環境変数の追加はない。
