# 個人データの端末間同期

2026-09-25実装。設定 → 自分の端末と同期。手動の保存・読み込み方式であり、バックグラウンドの自動同期や自動マージはしない。

## 初回接続（未実施）

Supabase SQL Editorの新しいクエリで `supabase/migrations/202609250003_personal_sync.sql` を実行する。既存の共有メモや個人のブラウザ保存データは変更しない。このSQLは初回用で、成功後は再実行しない。

両端末で同じLINEアカウントにログインする。先に元データがあるブラウザでクラウドへ保存し、もう一方でクラウドから読み込む。LINEログインの戻り先は `/settings/sync` に対応。スマホ用のLAN URLはSupabase Redirect URLsへの追加と実接続確認が別途必要。HTTPのLAN環境ではブラウザの暗号機能制約もあるため、ログインを含む実機確認はHTTPS環境を用意するのが確実。

## 対象と保護

イベント、チケット、買い物メモ、同行者、タグ、テーマのみを許可リストで保存する。認証トークン、共有メモ、同期の管理情報、バックアップは送信しない。全件スナップショットで最大10MB。個人用クラウドテーブルは本人のみ読み取り可能。書き込みはログイン本人をサーバーで確定する関数のみ許可し、版番号の一致が必須。別端末が保存した場合は競合として停止する。

初めて使う端末にクラウドと異なる既存データがあれば、クラウドを上書きする保存は止める。端末のJSONバックアップをダウンロードし、クラウドの内容を読み込んでから作業する。データの結合は未対応。

読み込み前はブラウザ内にもバックアップを追加保存する。バックアップ保存が失敗した場合は置き換えない。置き換え途中の失敗は元データに戻す。ダウンロードしたJSONは同じ画面から復元できる。バックアップには個人情報を含み得るため利用者本人が保管する。ブラウザ内バックアップは端末内に保持され、ログアウトでは個人データもバックアップも削除しない。共用端末でのアカウント分離はこの機能の対象外。

## 検証

PGliteで別アカウントの読み取り不可、直接書き込み不可、匿名の拒否、版番号競合を検証。クライアント側で秘密情報除外、バックアップ、保存容量不足時の保護を検証。実SupabaseへのSQL適用・PC/スマホの2端末同期は未確認。

## 実機確認の更新（2026-09-26）

ユーザーの操作と添付画面により、実SupabaseへのSQL適用、Chromeから保存、EdgeとiPhoneへの読み込みを確認。イベント5件・チケット1件・買い物メモ2件が一致。テーマの反映も確認。iPhoneのLINEログインは、Site URLをLAN用 `http://192.168.1.27:5174/auth/callback` に変更後に成功。明示したRedirect URLが採用されなかった根本原因は未確定。公開時はSite URLと許可URLを公開HTTPS URLに設定し直す。

iPhoneで同期画面の文字・余白・ボタンが大きすぎるとの要望を受け、同期ページ専用CSSと操作ボタンの短いラベルを追加。同期処理は変更していない。
