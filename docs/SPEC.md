# 🤍 SPEC

# 機能仕様

推しメモで提供する機能と、その動作仕様を定義します。

---

# イベント管理

イベントを起点として、すべての情報を管理します。

イベントには以下の情報を紐付けることができます。

- グッズ
- チケット
- 精算
- やること
- 通知

イベントを削除した場合は、関連するデータも削除されます。

---

# グッズ管理

グッズには購入状況を設定できます。

状態

- 未購入
- 保留
- 購入済み
- 売切れ
- 再入荷待ち
- 事後通販待ち
- 見送り

状態はユーザーが変更できます。

「売切れ」は販売状況を表し、
その後に

- 再入荷待ち
- 事後通販待ち
- 見送り

のいずれかへ変更できます。

---

# 特典計算

購入金額に応じて特典枚数を計算します。

イベントごとに

- 対象金額
- 特典内容

を設定できます。

特典枚数は自動計算されます。

---

# チケット管理

チケットでは

- 応募
- 当落
- 支払い
- 発券
- 入場

までを管理します。

必要に応じて

- 同行者
- 座席
- メモ

も登録できます。

---

# 精算管理

立替・共同購入を管理します。

管理内容

- 誰が支払うか
- 誰に渡すか
- 精算状況
- 支払い方法

精算内容は共有用にまとめて表示できます。

---

# やることリスト

やることリストには、

ユーザーが行動する必要がある項目のみ表示します。

例

- 支払い
- 発券
- 受け渡し
- 再入荷確認
- 事後通販開始

完了した項目は一覧から除外されます。

---

# 通知

通知は

「ユーザー自身が対応する必要があるもの」

のみ作成されます。

例

- 当落発表
- 支払い期限
- 発券開始
- イベント前日
- 再入荷予定日
- 事後通販開始
- 事後通販終了

通知タイミング

- 当日
- 1日前
- 2日前
- 3日前
- 1週間前
- カスタム

完了した通知は自動的に停止します。

---

# ホーム画面

ホーム画面では、

現在対応が必要な情報を優先して表示します。

表示例

- やること件数
- 未精算件数
- 今後のイベント
- 通知

詳細は各画面から確認できます。

---

# データ更新

情報を更新した場合は、
関連するデータも自動更新されます。

例

- 支払い完了
　→ やることリスト更新
　→ 通知停止

- 発券完了
　→ やることリスト更新
　→ 通知停止

- 精算完了
　→ 未精算件数更新

---

# 共有

共有機能では

- 精算内容
- 購入内容

などを、メッセージアプリへ共有できる形式で出力します。

共有内容は必要に応じて編集できます。

---

# エラーハンドリング

入力内容に不備がある場合は、
分かりやすいメッセージを表示します。

削除などの重要な操作では、
確認ダイアログを表示します。

# 基本方針

推しメモは、

**「ユーザーが今やるべきことを分かりやすくする」**

ことを最優先とします。

情報を管理することではなく、

**行動につながる情報を提供すること**

を目的として設計します。
## 買い物メモ（2026-09-25 実装）

イベント詳細から買い物メモへ移動できます。商品・購入者別数量・購入状況・メモ・特典設定をイベント単位でブラウザに保存します。
手入力による商品追加・編集・削除に加え、grandshop-companion-new の商品カタログ740件を任意で取り込めます。カタログは移行元のスナップショットで、自動更新はしません。旧アプリのブラウザに保存された購入数量などは自動移行しません。

購入者ごと／全員分で数量・金額を集計し、指定金額ごとの特典枚数と振り分けを表示します。売切れの未購入分と見送り分は合計から除外し、購入済み金額は保持します。全員分の特典は個別会計との端数差も表示します。
商品名・カテゴリ・キャラクター・発売月・購入状況で絞り込みできます。購入内容確認では数量がある商品を表示します。共有用テキストは作成・編集・コピーでき、アプリから自動送信しません。

保存キーは `oshi-memo-shopping-{eventId}`。タグ・やることリスト連携、旧アプリの保存データ移行、共有画像出力は未対応です。

## 友人との共有（接続準備段階）

Supabase Authのメール確認コードでログインし、共有用買い物メモへ参加する画面を追加。個人用とは別の共有コピーを作成し、共有画面内の購入者・数量・購入状態・メモを保存する。管理者がメールアドレスを指定して招待リンクを発行。閲覧者と共同編集者を区別し、7日間・1回限りの招待と取消・共有解除を実装する。サーバー側の権限検証と版番号による同時編集チェックを行う。約10秒間隔で最新データを読み込み、未保存入力は更新で上書きしない。

クラウド接続、メール配信設定、公開URLと実アカウントでの検証は未完了。詳しい手順と現段階の範囲は `SHARING_SETUP.md` を参照。


### チケットの販売方式（2026-09-26）
- 受付ごとに抽選／先着・一般販売を選択。既存の方式未設定データは抽選として表示する。
- 券種・料金は自由入力（一般、学生、S席、入場料など）。保存キーは互換性のため維持する。
- 一般販売では販売開始・購入期限と購入状況を表示し、当落日程・アイコンを表示しない。方式切替で既存の日程・支払い・精算データは削除しない。
- ホームのお知らせは受付開始後の申込／購入期限、抽選の発表日以降の結果確認を表示。状況の更新で解消する。購入確定後は支払い・精算のお知らせを引き続き表示する。

### メインジャンルからの登録（2026-09-28）
- ホームのイベント登録から、8ジャンルのアイコン付きタイル → 詳細入力へ進む。
- メインジャンルは保存前のみ選び直せる。保存後は固定し、追加タグで入力欄と機能を増やす。既存イベントは最初の既定タグをメインとして扱い、編集保存時に記録する。
- 名前以外は任意。映画は開催期間を省き、鑑賞日・上映開始／終了・スクリーン・上映形式を表示。他ジャンルは開催（通販は販売・受注）期間と、通販以外の個人の参加予定を分ける。
- 追加タグに応じて出演者、営業時間、入場方法、休館日、予約要否、発送予定などを表示。予約・整理券、飲食メニューのメモ、通販注文情報は任意追加。
- 保存後の買い物メモ／チケット入口もタグに応じて表示。既存データがある機能はタグを外しても表示・保持する。
- ホームの直近予定では参加日を優先する。開催期間や既存チケット・公演データは変更しない。
- 新しい項目も個人用保存データに含まれ、従来の手動クラウド同期で引き継ぐ。

### 公式URLから基本情報の取り込み（2026-09-28）
- ジャンル選択後の先頭に公式URLと読み込みボタンを配置。候補を確認し、チェックした項目だけ反映する。既存入力は初期選択しない。
- 単一EventのJSON-LD、ページタイトル、明示された開催期間・営業時間から候補を抽出。画像・JavaScript生成本文・認証ページの読み取り、AI推測、グッズ商品抽出は対象外。
- Vite開発／プレビューサーバーの `/api/official-page` で取得。HTTPS公開URLのみ、DNS検査・接続先固定・転送先再検査・容量／時間制限付き。静的公開先では別途サーバー実装の配備が必要。
- 公式サイトごとの表記で抽出率は異なる。読み取れない項目は手入力を維持する。

### 買い物メモの商品URL取り込み
- 「グッズページURLから追加」で公開HTTPSページを読み込み、Productの構造化情報から商品候補を表示する。候補は未選択で、商品名・単価を確認して追加する。既存の数量・購入状況は保持する。
- 画像中心のページは画像を選び、日本語・英語OCRで文字を読み取る。読み取り結果は編集可能。円価格と近接する商品名を候補化するが、列の順序や商品との対応は利用者が確認する。未読の価格を0円で補完しない。
- OCRはブラウザ内で実行。初回はエンジンと言語データのダウンロードが必要。ページと画像取得は開発・プレビュー用サーバー経由で、公開配置には同等のサーバー機能が必要。
